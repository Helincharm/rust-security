# Runtime isolation

The runtime API can request or run the dependency-free arithmetic unit test embedded at build time from `fixtures/runtime`. The CLI obtains an explicit human decision. The request itself only describes the fixture. Runtime execution accepts no source path, command, arguments, network destination, or image override. Reviewed Rust files remain inputs to the static analyzer.

## Prerequisites

- A trusted local Docker client and Linux engine with runc, cgroup v2, built-in seccomp and working resource controls. Windows uses the fixed Docker Desktop Linux named pipe and requires the system-installed Docker client in the OS default Program Files directory with a locally verifiable Docker Authenticode signature. Linux uses the fixed `/var/run/docker.sock` endpoint. Docker contexts, remote endpoints, CLI credentials, and proxy settings from the invoking environment are excluded. [Windows known folders](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid) · [Windows trust verification](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust)
- An owner-audited image already present in that engine. Build the framework with `HELINITY_RUNTIME_IMAGE_ID` set to the image's full `sha256:` image ID. Review the image and toolchain before pinning them. Docker's image ID commits to the image configuration and layer digests. The runner checks the inspected ID and uses Docker's never-pull policy. [Docker image inspection](https://docs.docker.com/reference/api/engine/version/v1.57/schemas/ImageInspect/) · [Docker container run](https://docs.docker.com/reference/cli/docker/container/run/)
- The image must supply `/usr/bin/env`, `/bin/sh`, `/usr/bin/cargo`, Rust and its linker, GNU `timeout` and `stat`, `id`, `grep`, `awk`, `cat`, and `mkdir`. Its image configuration must omit volumes and extra environment variables. Keep credentials and host integration software out of its layers.

The framework trusts the owner-provisioned image, Docker client, local engine and host account. An administrator who controls the host or daemon can change the execution boundary. Linux containers share the engine kernel. This execution path applies to the fixed fixture.

## Execution controls

- The framework inspects the newly created container by immutable container ID before starting it. It requires the intended image and exact fixed command, non-root user, read-only root filesystem, network mode `none`, separate container PID and cgroup namespaces, no IPC sharing, no added capabilities, no new privileges and built-in seccomp. It rejects requested binds, extra mounts, volumes, host devices, and published ports. [Docker container creation](https://docs.docker.com/reference/cli/docker/container/create/) · [Docker seccomp](https://docs.docker.com/engine/security/seccomp/)
- The container starts with a minimal environment. The fixture uses a 64 MiB memory-backed workspace with bounded file size. Cargo works offline with one build job and one test thread. The container is limited to 256 MiB of memory, zero swap, one CPU and 64 processes. Core dumps are disabled. The runner checks effective UID and GID, capabilities, seccomp, network interfaces, root mount and scratch workspace, and live cgroup limits before starting Cargo.
- The fixture runs under an in-container timer and a 45-second host-side deadline for the attached runtime command. Docker inspection and removal are also bounded. After every create attempt, the framework searches for the generated ownership label, confirms the name and label through inspection, and removes the container by its immutable ID. A create request that finishes after the cleanup checks can leave a stopped container. The error describes that possibility and gives the name. Docker logging is disabled. Subprocess output is capped and its contents stay out of the public result.

`status` checks the local engine and image prerequisites. Container-specific isolation checks occur after an approved request. If a prerequisite is unavailable or the verified configuration differs from the required settings, Cargo cannot start. Runtime analysis currently has no Miri, ASan, TSan or fuzzing integration.
